The problem

A plausible answer can conceal the wrong tool call, an invented argument, or an unfinished task. A useful evaluation needs to inspect what the agent actually did and explain why a response passed or failed. That feedback must be specific enough for another reviewer to apply consistently.

How I structure a review

  1. Establish intent: identify the requested result and the constraints stated by the user.
  2. Inspect actions: check the chosen tool, its arguments, and the returned evidence.
  3. Separate failure modes: score tool choice, argument grounding, and completion independently.
  4. Record feedback: point to the action or omission that explains the judgment.

A worked evaluation example

Synthetic example · created for this portfolio

This example illustrates the review method. It is not a client task, a production transcript, or a measured benchmark result.

User request: “Find the unpaid invoices for customer D-17. Do not send reminders.”

Observed tool call:

list_invoices({
  "customer_id": "D-17",
  "status": "paid"
})

Observed response: “You have no unpaid invoices.”

Tool choice · Pass
An invoice lookup matches the request.
Argument grounding · Fail
The status filter asks for paid invoices instead of unpaid invoices.
Instruction compliance · Pass
The observed action does not send a reminder.
Completion · Fail
A paid-invoice lookup cannot establish that no unpaid invoices exist.

Actionable feedback: repeat the lookup with the unpaid filter, inspect the returned records, and report only what that result supports.
